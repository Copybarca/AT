# Trans API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `trans-api` into the persistent transfer/orchestration service connecting extraction, one-fragment translation, and document building.

**Architecture:** Spring controllers delegate to transaction-scoped services and typed repositories. A single bounded `PipelineTaskQueue` owns local execution; PostgreSQL process rows and S3 objects remain authoritative across restarts.

**Tech Stack:** Java 21, Spring Boot 4, Spring MVC RestClient, Spring Data JPA, Liquibase, PostgreSQL 16, AWS SDK S3/MinIO, Maven/JUnit.

**Spec:** `docs/superpowers/specs/2026-08-19-three-service-pipeline-design.md`

## Global Constraints

- Only this service may access PostgreSQL and S3.
- Process status is only `IN_PROGRESS` or `COMPLETED`; absence means not started.
- The schema name is exactly quoted `"scheduled-processes"`.
- Percent is calculated from current positions and never stored.
- Worker calls use typed DTOs, bounded execution, and idempotent process commands.
- Tests use only local Docker PostgreSQL/MinIO and local HTTP stubs; no real model or production system.
- All production behavior is introduced by a failing test first.
