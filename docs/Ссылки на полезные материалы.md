# Ссылки на полезные материалы

## Tesseract OCR

Tesseract — локальный OCR-движок. Современный основной recognizer использует
LSTM-сеть для распознавания целой строки текста, но Tesseract не является LLM,
не переводит текст и не взаимодействует с `trans-flow` напрямую.

  документация актуальной ветки 5.x, установка, usage, traineddata и training.
- [Исходный код Tesseract](https://github.com/tesseract-ocr/tesseract) —

## Как работает текущий PDF-extractor

Ниже описан фактический путь в текущем коде
`PDF-extractor/src/pdf_extractor`.

### 1. Приём команды

`POST /internal/v1/extractions` получает multipart:

- JSON-часть `request` с `processId`, `bookId` и ожидаемым SHA-256;
- бинарную часть `file` с PDF;
- `Authorization: Bearer <SERVICE_TOKEN>`;
- `Idempotency-Key: extraction-<processId>`.

API проверяет token, idempotency key, лимит размера и сигнатуру `%PDF-`.
Файл потоково записывается в отдельный временный каталог job.

### 2. Снимок настроек и локальная очередь

При приёме job сервис:

1. вычисляет fingerprint команды и файла;
2. снимает immutable snapshot текущих `FragmentationSettings`;
3. передаёт один `ExtractionJob` объекту `ExtractionTaskQueue`.

Очередь имеет конечную capacity и настраиваемое количество workers. Повтор той
же команды считается duplicate, тот же `processId` с другим fingerprint —
conflict, заполненная очередь возвращает 429. После принятия API отвечает 202.

### 3. Проверка исходного PDF

Worker передаёт job в `PdfExtractionService`. Сервис вычисляет SHA-256 файла,
сравнивает его с командой и открывает документ через PyMuPDF.

### 4. Выбор способа распознавания каждой страницы

Для каждой физической страницы `TextLayerExtractor` вызывает
`page.get_text("dict")` и получает blocks → lines → spans:

- блоки сортируются по `y0`, затем по `x0`;
- собираются текст, bbox, font names и font sizes;
- определяется style;
- monospace и code-like блоки помечаются `CODE` и не переводятся;
- остальные блоки получают стабильный ключ вида `P0001-B001`.

Текстовый слой считается пригодным, если набралось не меньше
`MIN_SELECTABLE_CHARACTERS` буквенно-цифровых символов, по умолчанию 8.

### 5. OCR страницы

Если текстовый слой страницы непригоден, используется
`TesseractOcrEngine`:

1. страница рендерится PyMuPDF в RGB, по умолчанию 300 DPI;
2. вызывается `pytesseract.image_to_data(..., --psm 6)`;
3. слова ниже confidence threshold отбрасываются;
4. оставшиеся слова группируются по block/paragraph/line;
5. pixel coordinates масштабируются обратно в PDF points;
6. создаются те же `RawTextBlock`, что и для selectable text.

Поэтому дальнейшая фрагментация не знает, пришёл текст из PDF-слоя или OCR.

### 6. Извлечение и OCR изображений

Независимо от способа распознавания страницы `FigureExtractor`:

1. получает встроенные изображения через PDF xref;
2. извлекает исходные bytes без перерисовки;
3. получает положение изображения на странице;
4. назначает ключ `P0001-F001`.

Для надписей внутри изображения `TesseractImageOcrEngine` прогоняет:

- RGB-оригинал;
- grayscale + autocontrast;
- бинаризованный вариант;

каждый вариант в режимах PSM 6 и PSM 11. Результаты дедуплицируются по тексту
и bbox и становятся регионами `P0001-F001-R001`.

Текущее ограничение: confidence image-региона пока сохраняется как `null`;
page OCR использует confidence для фильтрации, но не публикует среднее значение
готового блока.

### 7. Фрагментация текста

`FragmentAssembler` обрабатывает итоговые блоки страницы:

- code/non-translatable блок остаётся одним неизменённым элементом;
- переводимый текст нормализует пробелы и делится на предложения;
- объединяются только соседние предложения;
- граница стремится к `FRAGMENT_MIN_SENTENCES..FRAGMENT_MAX_SENTENCES`;
- `FRAGMENT_BOUNDARY_TOLERANCE_SENTENCES` разрешает сдвиг к концу PDF-блока;
- фрагмент получает ключ с suffix `-F001`;
- `sourceHash` равен SHA-256 нормализованного текста фрагмента.

Настройки по умолчанию: 5–10 предложений, tolerance 2. Runtime settings API
влияет только на новые jobs.

### 8. Единый порядок элементов

После обработки всех страниц сервис объединяет текстовые фрагменты и
изображения, сортируя их по:

1. physical page;
2. вертикальной координате `y0`;
3. горизонтальной координате `x0`;
4. типу и исходному индексу.

Затем всему списку назначается непрерывный глобальный `sequentialNumber`
начиная с единицы.

### 9. Результат extraction

Формируется `ExtractionResult`:

- SHA-256 исходного PDF;
- версия extractor algorithm;
- ordered text/code segments;
- original images;
- image OCR regions;
- ожидаемые counts каждого типа.

### 10. Отправка в trans-api

`TransApiExtractionClient` публикует результат строго последовательно:

1. `segments:batch` — текст/code ограниченными batches;
2. `images` — каждое изображение отдельным multipart;
3. `image-regions:batch` — OCR-регионы batches;
4. `complete` — checksum, версия и итоговые counts.

Каждый HTTP response проверяется. Если batch или image upload не удался,
`complete` не отправляется. После успешного callback или контролируемой ошибки
временный каталог job удаляется.

## Граница с trans-flow

Прямого пути `Tesseract → trans-flow` нет:

```text
PDF/image
  → PDF-extractor
  → Tesseract при необходимости
  → ordered extraction data
  → trans-api / PostgreSQL
  → trans-api выбирает один отсутствующий перевод
  → trans-flow
  → trans-api сохраняет принятый перевод
```

Таким образом, Tesseract отвечает только за преобразование пикселей в исходный
текст. Выбор следующего фрагмента, translation validation, хранение результата
и запуск builder принадлежат `trans-api`.
