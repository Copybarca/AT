# Следующие шаги до базовой однопользовательской готовности

Дата обновления: 2026-08-21

## Что уже работает

Локальный Compose поднимает frontend, Nginx gateway, trans-api, PostgreSQL,
MinIO, PDF extractor, Ollama, translation flow и document builder. Проверен
реальный сценарий на двух страницах открытой английской книги Think Python:
extraction завершён, 8 из 8 фрагментов переведены, PDF собран и скачан через
публичный API. Также проверен ручной режим: перевод одного фрагмента сохранён,
старый PDF инвалидирован, новая сборка завершена, а ручной текст присутствует в
скачанном PDF.

## Предположения о границе первой версии

- Один пользователь работает локально и доверяет процессам на своём компьютере.
- Авторизация, разграничение доступа и многопользовательские конфликты пока не
  входят в базовый локальный сценарий.
- Одна книга имеет один выбранный целевой язык и один актуальный итоговый PDF.
- Ollama работает на CPU, если совместимая GPU не обнаружена.
- Polling статусов допустим; websocket не является блокером первой версии.

## Осталось обязательно

1. Исправить подтверждённую пересборку готового PDF без предварительного ручного
   изменения. Сейчас повтор с тем же build process корректно требует
   replaceExisting=true, но downstream idempotency считает неизменившийся
   processId повтором. Рекомендуемое решение — создавать новую ревизию/build
   process с новым id, сохраняя единственный актуальный translatedPath.
2. Добавить failure callback от document-builder в trans-api. Сейчас успешный
   callback работает, но внутренняя ошибка builder может оставить backend-статус
   IN_PROGRESS; аналогичную гарантию следует проверить для extractor.
3. Зафиксировать выполненный ручной E2E как повторяемый скрипт: создание
   двухстраничной копии, upload, polling, download, ручное изменение и rebuild.
4. Добавить браузерный smoke-тест загрузки через форму, чтобы проверять не только
   REST-контракт, но и пользовательский путь PrimeReact.
5. Прогнать отдельные fixtures: текстовый PDF с изображением, сканированный PDF,
   пустую страницу, большой фрагмент и PDF с некорректной структурой.
6. Добавить удаление документов из списка и карточки, включая документы с
   ошибкой загрузки или обработки. Удаление должно требовать подтверждения и
   согласованно очищать запись в БД, исходный файл, промежуточные артефакты и
   итоговый PDF, не затрагивая другие книги.
7. Показывать подробную и безопасную причину ошибки вместо общего статуса:
   проблемную стадию, понятное описание, время ошибки и рекомендуемое действие.
   В частности, ошибки имени файла, формата, размера, OCR, модели и сборщика
   должны различаться и быть доступны в списке и карточке документа.
8. Устранить визуальное мерцание при периодическом обновлении статусов книг.
   Polling не должен сбрасывать таблицу в loading-состояние, менять прокрутку,
   фокус или выделение: данные следует обновлять фоново и точечно. Websocket или
   SSE можно использовать как транспорт, сохранив спокойный polling fallback.
9. Показывать фактический этап и прогресс разбора документа. Extractor должен
   передавать через trans-api как минимум состояния `QUEUED`, чтение PDF,
   обработку страниц (`currentPage / totalPages`), OCR, извлечение изображений,
   сегментацию, сохранение результатов и `COMPLETED`/`FAILED`. Frontend должен
   отображать название текущего этапа, счётчик страниц и последнюю активность,
   не подменяя неизвестный прогресс искусственными процентами.
10. Сделать кнопку «Назад» визуально заметнее: использовать для неё коричневый
    акцент и ту же выразительность, что у основной кнопки «Загрузить файлы»,
    сохранив различимые состояния hover, focus, disabled и достаточный контраст.

## Желательно после базовой готовности

- Добавить выбор более лёгкой Ollama-модели для слабых ПК; qwen3:8b даёт
  приемлемый результат, но первый CPU-фрагмент до отключения reasoning занимал
  несколько минут. С think=false дальнейшие фрагменты обрабатывались заметно
  быстрее.
- Добавить экран диагностики с последней ошибкой каждой стадии и безопасной
  кнопкой повтора.
- Устранить предупреждения Fontconfig, создав writable cache directory в image
  document-builder.
- Добавить резервное копирование Compose volumes и документированный сброс
  локальных тестовых данных.

## Критерий завершения первой версии

С чистого checkout одна команда поднимает healthy-стек; загрузка обычного и
сканированного PDF из браузера без ручных API-вызовов заканчивается скачиваемым
PDF; ошибка любой стадии видна и повторяема; ручное изменение и подтверждённая
пересборка проходят повторяемый E2E-тест.
